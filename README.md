# Lampa: Аниме онлайн + Кино онлайн (HDrezka прямым потоком)

Три части в одном репозитории:

- **anime_online.js** (v1.16.0) — кнопка «Аниме онлайн» на карточке (AniLibria, YummyAnime, YummyAnime.TV). У YummyAnime и YummyAnime.TV озвучка и серия выбираются в Lampa, а видео играет её собственный плеер: сервис на VPS отдаёт прямые HLS-ссылки плеера Kodik.
- **kino_online.js** (v2.0.0) — кнопка «Кино онлайн»: фильмы и сериалы **HDrezka прямым HLS-потоком**; если сервер недоступен — запасной источник Kinokrad (плеер окном).
- **kino_extractor.py** (v1.4.1) + **worker.js** — серверная часть: экстрактор HDrezka, разбор Kodik и видео-прокси (HLS) на VPS, CORS-прокси и мост на Cloudflare.
- **cub_vps.js** (v1.0.0) — запросы CUB идут через наш VPS: без этого карточка фильма виснет, потому что `cub.*` из РФ недоступен.
- **slow_check.js** (v2.0.0) — диагностика: журнал сетевых запросов (Настройки → «Журнал запросов»).

## Установка плагинов

**Одна ссылка на всё** — в Lampa → Настройки → Расширения → Добавить плагин:


а если Pages недоступен — те же файлы с jsDelivr. Обе кнопки («Аниме онлайн» и «Кино онлайн»)


Резерв: `https://cdn.jsdelivr.net/gh/tverzar/lampa-anime-online@main/<файл>`.

**Плагин против зависания карточки** — `cub_vps.js` (запросы CUB идут через наш VPS, см. ниже):

**Диагностика зависаний** — `slow_check.js`: журнал сетевых запросов (что не отвечает или
тянется дольше 4 секунд), открывается в Настройках пунктом «Журнал запросов»:


## Как работает «Кино онлайн» 2.0.0

1. Кнопка **«Кино онлайн»** на карточке фильма.
2. Поиск по названию на HDrezka через свой экстрактор (см. ниже).
3. Выбор фильма или сериала (в подписи год и тип).
4. Выбор озвучки (у фильмов до 10 вариантов, у сериалов до 20).
5. Для сериалов — выбор сезона и серии.
6. Воспроизведение в **штатном плеере Lampa** (hls.js): без iframe, без рекламы чужих сайтов, переключение качества прямо в плеере.
7. Если экстрактор недоступен — плагин уходит на запасной источник **Kinokrad** (плеер открывается окном, как в версии 1.x).

## Серверный экстрактор: зачем он нужен

HDrezka закрыта тремя защитами, которые браузер телевизора обойти не может:

| Защита | Что происходит | Как обходим |
| --- | --- | --- |
| Антибот **Anubis** (proof-of-work) | Запрос без пройденного челленджа получает страницу-заглушку | Экстрактор решает `sha256(randomData + nonce)` с нужным числом ведущих нулей и получает cookie `techaro.lol-anubis-auth` |
| Гео-замок по `CF-Connecting-IP` | Не-РФ/СНГ адрес получает `success: true`, но `url: false` — потока нет | Экстрактор подставляет в этот заголовок **IP клиента** (адрес, с которого пришёл запрос плагина) |
| Привязка ссылки к IP клиента | CDN `stream.voidboost.one` отвечает 404, если манифест запрашивает «не тот» адрес | Видео качает **сам телевизор**: ссылка минтится под его адрес, и CDN видит тот же адрес |

Отсюда главное ограничение: **поток нельзя проксировать** через сервер — сервер только выдаёт ссылку.

### Ручки экстрактора

Все запросы идут через `/kino/<token>/`:

| Ручка | Параметры | Ответ |
| --- | --- | --- |
| `/health` | — | состояние, версия, IP заказчика |
| `/search` | `q`, `limit` | список фильмов и сериалов |
| `/info` | `url` | id, озвучки, сезоны, признак сериала |
| `/episodes` | `url`, `translator`, `season` | список серий выбранного сезона |
| `/stream` | `url`, `translator`, `season`, `episode` | ссылки на HLS по качествам и субтитры |

Пример:

```bash
curl "https://<адрес>/kino/<token>/search?q=Интерстеллар&limit=3"
```

### Развёртывание на своём сервере

```bash
# 1. сервис
install -m 755 kino_extractor.py /opt/kino-extractor/kino_extractor.py
echo '{"token": "СВОЙ_ТОКЕН", "port": 8791}' > /etc/kino-extractor.json
chmod 600 /etc/kino-extractor.json

# 2. systemd
cat > /etc/systemd/system/kino-extractor.service <<'UNIT'
[Unit]
Description=kino-extractor (HDrezka для Lampa)
After=network-online.target

[Service]
ExecStart=/usr/bin/python3 /opt/kino-extractor/kino_extractor.py --config /etc/kino-extractor.json
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
UNIT
systemctl enable --now kino-extractor

# 3. nginx: http на 80 и https на 8443
#    сертификат Let's Encrypt на имя вида 94.156.237.213.nip.io (webroot + certbot)
```

Адрес экстрактора задан в `kino_online.js` в массиве `EXTRACTORS`: первый — свой адрес
с точным IP клиента, второй — мост через Cloudflare Worker (`/kino/*` в `worker.js`,
он передаёт адрес клиента в заголовке `X-Kino-Client-IP`).

Cloudflare Worker **не может** обращаться по голому IP (ошибка 1003), поэтому в `worker.js`
сервис указан именем (`http://94.156.237.213.nip.io`), а не `http://94.156.237.213`.

## Аниме онлайн (anime_online.js)

| Источник | Токен | Как воспроизводится |
| --- | --- | --- |
| AniLibria | не нужен | прямые HLS 480p/720p/1080p в плеере Lampa, плейлист серий |
| YummyAnime.TV | не нужен | Kodik прямым HLS в плеере Lampa: озвучка и серия выбираются в Lampa |
| YummyAnime | не нужен | Kodik прямым HLS в плеере Lampa, остальные плееры (Alloha, CVH, Sibnet) — окном |

Прямой XHR к `kodikplayer.com` из Lampa браузер режет (нет CORS-заголовков), поэтому ссылки
минтит сервис на VPS: плагин отдаёт ему ссылку плеера, сервис отвечает готовыми HLS-ссылками
(360p/480p/720p), а видео играет штатный плеер Lampa — работает пульт, нет чужой рекламы.
Ссылки Kodik не привязаны к IP и не требуют Referer, так что телевизор качает поток сам.

Ссылки плеера Kodik приходят в двух видах: `/serial/<id>/<hash>` (страница релиза) и
`/season/<id>/<hash>` (такой отдаёт YummyAnime — это озвучка + сезон); сервис разбирает оба.

## Прокси Cloudflare

`worker.js` умеет два маршрута: `/proxy?url=` — CORS-прокси для плагинов (только домены
из белого списка: `api.yani.tv`, `yummyanime.tv`, `kinokrad.cc`, `kinogo.*`, домены Kodik)
и `/kino/*` — мост к экстрактору на VPS для случаев, когда телевизор не может достучаться
до сервера напрямую.

## CUB через VPS (cub_vps.js)

Lampa на карточке фильма запрашивает у CUB блок «Реакции» (`/api/reactions/get/...`) и, если
ответа нет, карточка виснет (issue yumata/lampa#256). Из РФ домены CUB (`cub.best`, `cub.red`,
`cub.black`, `durex.monster`) не открываются, поэтому запросы уходят в никуда.

`cub_vps.js` подменяет адрес таких запросов на наш сервер, а сервер уже сам спрашивает CUB:

| Запрос Lampa | Куда идёт с плагином |
| --- | --- |
| `https://cub.best/api/...` | `https://94.156.237.213.nip.io:8443/cub/api/...` |
| `https://tmdb.cub.best/3/...` | `https://94.156.237.213.nip.io:8443/cubtmdb/3/...` |
| `https://cub.black/plugin/...` | `https://94.156.237.213.nip.io:8443/cub/plugin/...` |

Остальные запросы (TMDB, картинки, наши плагины) не трогаются. Реализовано перехватом
`XMLHttpRequest.open`, `fetch`, `setAttribute('src')` и сеттера `src` у скриптов, картинок и iframe.

На стороне сервера это два `location` в `/etc/nginx/conf.d/kino-https.conf`: `/cub/` →
`https://cub.best/` и `/cubtmdb/` → `https://tmdb.cub.best/` с подменой `Host`/SNI, CORS
(эхо `Origin`, `Allow-Credentials`, предварительный `OPTIONS` → 204) и поддержкой WebSocket.

Проверено с домашнего IP через прокси: реакции `movie_157336` — 200 и те же 539 байт, что и
напрямую с `cub.best`; TMDB-прокси `3/configuration` — 200; POST и скрипты плагинов CUB
(208 КБ JS) отдаются. Тест подмены адресов: 13 случаев (зеркала, `tmdb.*`, чужие домены вида
`cub.best.evil.com`, повторный проход) — 0 ошибок.

## Видео через наш сервер (anime 1.16.0 + сервис 1.4.1)

Провайдер закрывает CDN Кодика (`solodcdn.com`): телевизор получает от сервиса ссылку на поток, плеер открывается — и закрывается, потому что сам поток скачать не может. На компьютере тот же адрес открывается только через AntiZapret, у телевизора его нет. Поэтому видео Кодика по умолчанию идёт через наш сервер:

- `playlist.m3u8?url=<плейлист>&base=<наш адрес>` — сервис скачивает плейлист с CDN и переписывает все ссылки на нас; отдаёт с типом `application/vnd.apple.mpegurl` (иначе AVPlayer на Apple TV считает ответ текстом и не играет).
- `segment.ts?url=<кусок>` — сервис отдаёт сегмент как `video/mp2t`. Прежние имена `/hls` и `/segment` работают как синонимы.
- В плагине переключатель `VIDEO_VIA_SERVER` (в начале блока плеера): по умолчанию `true` — видео всегда через наш сервер; `false` — играть напрямую, если у зрителя CDN открыт (тогда плагин ещё и проверяет доступность сам, `fetch` в режиме `no-cors`).
- При первом включении видео в сессии показывается уведомление «Видео идёт через наш сервер».

Проверка сервиса: плейлист через `/playlist.m3u8` — 200, `application/vnd.apple.mpegurl`, 85 348 байт, 237 сегментов, ссылки ведут на наш `/segment.ts`; сегмент через `/segment.ts` — 200, `video/mp2t`, 2 605 304 байта, первый байт `0x47` (MPEG-TS).

## Ограничения

- Качество без входа на HDrezka — **360p** (сайт отдаёт больше только аккаунтам).
- Ссылка на поток живёт ограниченное время и привязана к IP: плагин получает новую на каждый запуск.
- Если у телевизора DNS блокирует `voidboost.one` (бывает у провайдеров и у локальных антизапретов), манифест не загрузится — тогда остаётся запасной источник Kinokrad.
- Источники пиратские: доступность и реклама зависят от площадок.
